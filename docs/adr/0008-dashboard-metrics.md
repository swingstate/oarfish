# ADR 0008: Dashboard metrics from files, streamed with Server-Sent Events, sampled only while watched

- Status: **Accepted** (2026-10-28, accepted by the project owner). Decision 8 is amended; see there.
- Date: proposed 2026-10-27, accepted 2026-10-28
- Amended after R1 (2026-11-06, `docs/DECISIONS.md` D-C72, D-C73): section "Amendment after R1" at the end (optional history, default route and DNS display).
- Amended after S1 (2026-11-06, D-C78), by task N0 (2026-11-27), by the tasks N1 and ST1 (2026-11-27, D-C104) and by the fix step SF1 (2026-11-28): sections "Amendment after S1", "Amendment: N0 as implemented", "Amendment: N1 and ST1 as implemented" and "Amendment: SF1 as implemented" at the end.
- Gate: G5

## Context

Gate G5 adds the Home page with live values of the device (spec 6.3, 7.2, 8.7). The device is a Raspberry Pi Zero 2 W with 512 MB of RAM, an SD card and a service sandbox without `AF_NETLINK` (unit file, ADR 0006). The idle budgets are strict: at most 35 MB RSS, under 1 % of one core in a five-minute average, and no high-frequency writes to the SD card (ORB-NFR-001, -003, -009). ADR 0007 and decision D-C19 already settled that detection reads files and runs no program. The specification does not say how metrics are collected, delivered or bounded. This ADR records the answers. Each numbered decision was a `D-DRAFT-G5-nn` item in the pull request of Gate G5 and is now a confirmed decision D-C31 to D-C41 in `docs/DECISIONS.md` (decision 10 refers to D-C29).

## Decisions

**1. Metrics are read from files; no program runs (extends D-C19).** CPU time from `/proc/stat`, load, uptime, memory and swap from procfs, the host name from `/proc/sys/kernel/hostname`, frequency and governor from `cpufreq` in sysfs, temperatures from `thermal_zone*` and `hwmon*`, mounts from `/proc/self/mountinfo`, network state and counters from `/sys/class/net/<if>/`, addresses from `/proc/net/fib_trie` and `/proc/net/if_inet6`. All reads go through the read-only, size-limited file source of ADR 0007. The one system call is `statfs(2)` (`syscall.Statfs`, no cgo) for the size of a mounted file system; it needs no privilege and runs no program. The file allow-list is enforced by a test. Why: it is the same guarantee as for detection, it works under the unchanged unit, and it is testable with fixture trees.

**2. No netlink.** `net.Interfaces` and `net.InterfaceAddrs` use netlink, which the unit does not allow (`RestrictAddressFamilies` has no `AF_NETLINK`). Network data therefore comes from sysfs and procfs only. Cost: `/proc/net/fib_trie` lists IPv4 addresses without their interface. To assign them, the collector reads `/proc/net/route` as well (the directly connected networks per interface) and gives an address to the interface whose network contains it. An address without such a route is not shown. This reads one file more than the task text names; it is the only file-based way to get the assignment. Hardware note: reading `/proc/net/route` worked on the Raspberry Pi Zero 2 W under the unchanged service unit (`v0.1.0-alpha.4`, see [`INSTALL.md`](../INSTALL.md#gate-g5-dashboard)).

**3. Server-Sent Events, not polling.** `GET /api/v1/events` pushes one `metrics` event about every two seconds, an `alerts` event when the list changes, a `history` event once at the start and a heartbeat comment every 15 seconds. `GET /api/v1/metrics` returns one snapshot for the first paint. Why: one open connection is cheaper for a Pi than a request every two seconds (headers, routing, JSON per request), and the browser reconnects by itself. Cost: a stream holds a connection and a goroutine; see decision 6.

**4. Sampling only while somebody watches.** The sampler has no goroutine, no timer and no file read until the first stream client connects, and it stops when the last one leaves. While watched it samples every 2 seconds; storage, network addresses, link speed, the sensor list and the governor are read every 30 seconds. The browser closes the stream when its tab is hidden. Why: ORB-DASH-006 asks for adaptive intervals and no permanent collection; an unwatched dashboard costs nothing.

**5. History is a ring in memory only.** 60 points per series (CPU usage, memory use, CPU temperature), that is two minutes at the default interval, about 3 KB. It is cleared when the last client leaves, so it never shows stale data and nothing is written to the SD card (ORB-NFR-009).

**6. Everything is bounded.** At most 4 stream clients (the fifth gets a typed `503`), 16 sensors, 8 mounts (after de-duplication, from at most 64 candidate devices), 8 interfaces, 4 addresses per interface and family, every file read limited in size, every directory listing limited to 512 entries. A client that does not read is dropped by a per-write deadline of 10 seconds. The sampler never waits for a client: each client holds one frame and the newest replaces the unread one.

**7. The stream and the server timeouts.** `http.Server.WriteTimeout` covers a whole response and would end every stream after 30 seconds. The stream handler sets its own write deadline (`http.ResponseController`) before each write instead, which replaces the server's. `ReadTimeout` needs no change (verified by a test with 200 ms timeouts). On shutdown the handler closes all streams; without that, a graceful `Shutdown` would wait for connected browsers until its timeout. Why per-write deadlines rather than no timeout: a stalled client must free its goroutine and its slot.

**8. Alert rules are code with named thresholds (amended, see the end of this decision).** A small rule engine with three levels. Alerts carry a stable id, a level and cause, impact and next step as translation keys with parameters; Go builds no user text. Thresholds are constants in one table (docs/DASHBOARD.md) and are not configurable in G5. Table: CPU temperature 70 / 80 °C; memory available below 15 / 8 %; swap in use from 1 MiB (amended below to 25 percent of the swap total); a real file system above 85 / 95 %; no link on any interface; one-minute load above the number of cores; informational for Generic Mode and Compatible. The 1 MiB for swap is a choice of this ADR: the task text says "swap in use", and a few KiB that the kernel parks there are normal.

**Amendment (2026-10-28, project owner).** The swap alert becomes relevant from **25 percent of the swap total in use**, replacing "from 1 MiB". For context: the hardware reading of `v0.1.0-alpha.4` found 1.5 MiB parked in swap without any swap activity, which is above the old threshold. The amendment is implemented by the alert tuning task (D-C42) after `v0.1.0-alpha.4`; that release still alerts from 1 MiB. The rule needs a known swap total greater than 0; with no swap configured it raises nothing, and the text says "occupied", not "swapping", because occupied swap is not swap activity. The informational alert for the Compatible tier was removed by decision D-C44 (the status stays in the Home header and on the Device page); the informational alert for Generic Mode stays.

**9. Privacy by construction.** The host name and the IP addresses are shown on the live page and in the live API only. The hardware address of an interface (`/sys/class/net/<if>/address`) is never read. IPv6 link-local addresses and IPv6 addresses built from the hardware address (EUI-64) are not shown, because both contain the MAC address. Mount points under `/home/<user>`, `/media/<user>` and `/run/media/<user>` are shortened so that no user name appears. Machine id, serial number, environment, process list, user databases and SSH data are never read. A test lists every file the collector may open.

**10. The listen guard (D-C29).** The binary refuses to start unless `-listen` is a literal loopback IP address with a port. No override. This stays until Gate G5.1 (amended by D-C48: it stays after G5.1 as well, until LAN access and HTTPS are designed, D-D10).

**11. Frontend.** Svelte 5, no chart library, no new dependency. Sparklines are inline SVG. Transfer rates are computed in the browser from the counters. Only the alert list is an `aria-live` region. The old "Status" view and its `/healthz` check are replaced by Home, whose connection state tells the same thing and more.

## Consequences

- A request to `/api/v1/metrics` without a stream reads the device twice, 250 ms apart, so that CPU usage exists; the answer is reused for one second.
- The first sample of a stream is published 0.5 seconds after the first client connects, so that CPU usage is not empty.
- More than four browser windows on Home are refused until one closes. Browsers also limit connections per host; the cap keeps the device from being the one that gives.
- The collector reads about 15 small files per sample. The benchmark in `internal/metrics` measures the work, not the time on the device. Idle CPU and RSS were measured on one Raspberry Pi Zero 2 W with `v0.1.0-alpha.4` (docs/INSTALL.md, docs/DASHBOARD.md "Verification status").
- Not decided here: throttling and undervoltage warnings (ORB-DASH-004, needs a safe board adapter), the plugin and application summary (ORB-DASH-007), the resource view of external daemons (ORB-NFR-017), persisted history, configurable thresholds, authentication of the API (Gate G5.1).

**R1.1 Optional history (amends decision 5 and D-C35; refines decision 4).**

- **Owner decision:** the live display and the live ring of decision 5 (60 points, memory only, cleared when the last client leaves) are unchanged. Sampling for the live display stays only while somebody watches (decision 4).

## Amendment: N0 as implemented

Recorded with the pull request of task N0 (2026-11-27; `docs/ROADMAP.md`, row N0; ORB-NET-001, D-C72). It implements the proposal S1.3 for two of its three files and R1.2 for the default route and the DNS servers. Labels: **fact (repository)**, **implementation choice** (made by the implementation agent, for the owner's review), **open**. Evidence: class C (tests and CI). Nothing here is observed on a device yet; the device check follows the release. Decisions 1 to 11, R1 and S1 are unchanged except where this section says so. D-C31 and D-C32 stay in force: no program, no netlink, files only.

**N0.1 Sources (fact).** IPv4 default route: the default row of `/proc/net/route`, from the same read that assigns the IPv4 addresses (decision 2). IPv6 default route: `/proc/net/ipv6_route`. DNS servers: `/etc/resolv.conf`. All three are read with the slow tier (every 30 seconds, decision 4), through the file source of ADR 0007. `/proc/net/wireless` (S1.3) is not read: signal strength belongs to N1.

**N0.2 Rules (implementation choice).**

- A default row has destination and prefix length 0 (for IPv6 also a source prefix length 0), the up flag, no reject flag, and an interface other than `lo` whose name has the characters of a kernel interface name. A row with the gateway flag must name a gateway that is not unspecified, loopback or multicast; a row without the flag must name none. This skips the unreachable default route that the kernel keeps on `lo`.
- **Several default rows:** the lowest metric wins; on equal metrics the first row of the file. That is the route the kernel uses for a new connection; equal-cost multipath is not shown.
- A default route without a gateway (a point-to-point link, a tunnel) is shown with its interface only. An IPv6 link-local next hop is shown with its interface as the zone, because it means nothing without it.
- **Privacy (follows decision 9):** a next hop or a name server whose IPv6 address is built from a hardware address (EUI-64, `ff:fe` in the middle) contains the router's MAC address. Its address is never shown; a route keeps its interface and says that the address is hidden, and hidden name servers are counted. The task asks to show link-local gateways with their interface; this choice shows every link-local gateway that does not hold a MAC address, and is meant to agree with decision 9. *Assumption, not checked:* the next hop of the reference device's router may be of this kind; the device check will say which.
- **DNS:** only `nameserver` lines count. The address is the second field; everything after it is ignored, and so are comments, `search`, `domain`, `options` and `sortlist`. Only the parsed address reaches the output, never text from the file. A line whose address does not parse, is unspecified or multicast, or has a zone that is not an interface name, is skipped and does not count. At most three servers, in file order: the C library asks only the first three (`MAXNS`), so a fourth would show a server that is never asked. An IPv4-mapped address is shown as IPv4.
- **Local resolver stub:** a loopback server is shown as it is and marked local; the page says that it is a resolver on the device and that the servers behind it are not visible. The fallback design of S1.2 (reading the servers a stub forwards to) is **not built**. (Pointer: a stub was first observed by the Ubuntu probe, [`UBUNTU_PROBE.md`](../UBUNTU_PROBE.md) U3; the fallback is built by task N1, see N1.3 below.)

**N0.3 Bounds (fact).** `/proc/net/ipv6_route` 256 KiB (the limit of the other network tables), `/etc/resolv.conf` 64 KiB; a file above its limit gives its part the status `unreadable`, it is not cut. Every parser reads at most 8192 lines. The parsers have fuzz targets (`FuzzParseDefaultRoute4`, `FuzzParseDefaultRoute6`, `FuzzParseResolvConf`).

**N0.4 Fail soft (fact).** Each of the three parts has its own status: `found`, `none` (the file was read and holds no value) or `unreadable` (missing, unreadable or too large). A failed part leaves the others and the rest of the snapshot as they are; the page shows "Nicht verfügbar", "Keine" or "Keiner eingetragen".

**N0.5 Allow-list and unit (fact).** `proc/net/ipv6_route` and `etc/resolv.conf` were added to the metrics allow-list, the list that `TestMetricsOpenOnlyAllowListedFiles` enforces (`backend/internal/platform/privacy_test.go`). The service unit is **not changed**, and it does not need to be: there is no allow-list in the unit. `ProtectSystem=strict` mounts `/usr`, `/boot` and `/etc` read-only, which leaves them readable; `ProtectKernelTunables=yes` makes `/proc/sys` read-only and does not touch `/proc/net`; the unit sets no `ProtectProc`, `ProcSubset`, `InaccessiblePaths`, `TemporaryFileSystem` or `PrivateNetwork`, so `/proc/net` shows the host's network namespace and `/run` (where `/etc/resolv.conf` often points) stays visible. `/proc/net/route` is already read under this unit (decision 2). *Open until the device check:* that the service user reads both new files under the real hardening.

**N0.6 API (fact).** The metrics snapshot (`GET /api/v1/metrics` and the `metrics` event) gains the field `routing`; `GET /api/v1/device` gains `hardware.memory_installed_bytes` from the matched board profile (ADR 0007, pointer of task N0). Both are added fields: the schema versions stay 1. No route was added. Shapes: [`DASHBOARD.md`](../DASHBOARD.md#api), [`DETECTION.md`](../DETECTION.md#api-get-apiv1device).

**N0.7 Two fixes of G7-FIX1 in the same task (fact).** The embedded frontend is now sent with `Cache-Control: no-cache` for `index.html` and every file without a content hash, and with `public, max-age=31536000, immutable` for the hashed files of Vite; the update page loads the new page itself once `/healthz` reports another version than the one that served it (ADR 0011 A8.8, finding). The update page's password step says "Das Passwort ist falsch." Both are described in [`UI.md`](../UI.md#update-page-step-g68).

**N0.9 Device result (release `v0.1.0-alpha.15`, 2026-11-27).** *Device observation, one device, one image, one moment*; the reference device of ADR 0011 A7.2. Class D. Nothing is Verified, and the support status stays Compatible. The raw outputs stay outside this repository; host name, user name and addresses are left out.

- **Method.** The implementation agent read the device over SSH, with `sudo` for reading only. The journal of the new process has no warning, no error and no permission error.
- **The page (the owner's observation).** The network card shows "Standardroute und DNS" with the IPv4 route "`<gateway>` über wlan0", the IPv6 route "Router über wlan0 (Adresse verborgen, sie enthält eine Hardwareadresse)" and two DNS servers without "(lokal)". So the service read all three files under the unit hardening: an unreadable file would show "Nicht verfügbar". The Gerät page shows "512 MiB (davon 415 MiB nutzbar)" and "Nur 512 MiB Arbeitsspeicher"; MemTotal on the device is 415 MiB.
- **Cache headers (N0.7), observed.** Through the tunnel, `/` answers `Cache-Control: no-cache` and the hashed script `public, max-age=31536000, immutable`.
- **The reload after an update (N0.7): not observable in this update.** The update was started from the page of `v0.1.0-alpha.14`, whose code has no reload logic. After the restart that page took the session-loss path. After the login it showed the result of the update and, on the Dashboard, its old interface without the routing part, until the owner reloaded once (a normal reload, not a hard one). That is the behaviour of the old page, not a fault of the fix. The fix is first observable on an update that starts from `v0.1.0-alpha.15` or later. Until then it is class C.

Decisions 1 to 11, R1, S1 and N0 stay in force except where this section says so: files only, no program, no netlink (D-C31, D-C32).

**N1.1 Prefixes (fact).** Every shown address now has its prefix length, in the added members `ipv4_cidr` and `ipv6_cidr` of an interface (same addresses, same order as `ipv4` and `ipv6`, which stay plain strings). The IPv4 prefix is that of the connected route of `/proc/net/route` by which the address was assigned to its interface (decision 2, the most specific one); the IPv6 prefix comes from `/proc/net/if_inet6` (S1.2). No new file.

**N1.2 Signal (fact; tier: implementation choice).** `/proc/net/wireless` (16 KiB limit) gives per Wi-Fi interface the link quality and the level. The kernel prints the level minus 256 when the driver reports dBm, so a dBm level is negative (`-127` to `-1` accepted); a positive level has no unit and is not shown as dBm. The link quality is on the driver's own scale (0 to 255 accepted; the file names no maximum). At most 16 interfaces, each name once; a line of another shape is skipped (`ParseWireless`, fuzz target `FuzzParseWireless`). The member `signal` (`level_dbm`, `link_quality`) is set only for an interface of kind `wifi` that the file lists, else `null`; a missing, unreadable or oversize file gives no signal (fail soft). **Tier:** the fast tier, every sample, because the value changes from second to second and costs one small file read per sample, only while somebody watches, and only when a Wi-Fi interface exists (decision 4). **The plain word** on the page (good from -60 dBm, fair from -70 dBm, weak below) is a proposal of `docs/UI.md`, not a measurement.

**N1.3 The servers behind a resolver stub (implementation choice; fixes U3).** When `/etc/resolv.conf` names at least one server and every one is a loopback address, `/run/systemd/resolve/resolv.conf` is read (64 KiB limit) with the same parser and the same rules of N0.2: `nameserver` lines only, at most three, an EUI-64 address hidden and counted. Its servers are shown, and `dns.via_local_resolver` is `true`; the page says they are used through the resolver on the device. The fallback is used only when that file is readable and names at least one server that is not a loopback address; without the file, when it is unreadable or over its limit, when it names no server or a loopback server, the behaviour of N0 stays (the stub, marked local). A server list of `/etc/resolv.conf` with any non-loopback server never reads the file.

**N1.4 Page (fact).** The page Netzwerk (`#/network`, group System, before Aktivität, specification 7.2) uses the live data path of the Dashboard and adds no route: per interface its name, kind, link state, speed, the addresses with prefix and the counters; for Wi-Fi the signal; the default routes and the name servers. **No SSID** row and no placeholder for it (specification 7.1; S1.5 stays open). No hardware address anywhere (decision 9). The Dashboard's network card stays and links to the page ([`UI.md`](../UI.md#network-page-task-n1)).

**ST1.1 Device, disk and removable flag (implementation choice).** A real file system of the snapshot (decision 6, unchanged rules and bound of 8) gains `device` and `disk`, the kernel names of its block device and its disk, read from the sysfs link `/sys/dev/block/<major>:<minor>` (built from the two integers of the mount, as the detection of ADR 0007 does): the link's last element is the device, and for a partition the element before it is the disk. A name must have 1 to 32 letters, digits, `_` or `-`; a link of another shape gives `""`. **The mount source is never used** for the device: a source by UUID or label, `/dev/root` and every other text leave the output; a UUID, a partition ID or a label is never shown. `removable` is the kernel's removable flag of the disk (`/sys/block/<disk>/removable`, `0` or `1`, else `null`), `usb` is true when the link passes a `usbN` element. The identity files of a medium (serial, CID, CSD) and `uevent` are never read.

**ST1.2 Other mounts (implementation choice).** The added member `mounts` lists the mounts a person may store files on or rely on that are not real storage: kind `memory` (tmpfs, ramfs), `overlay` and `network` (nfs, nfs4, cifs, smb3, smbfs, 9p), outside the system areas `/proc`, `/sys`, `/dev`, `/run`, `/var/lib` and `/snap` (a mount at `/` itself is listed), one per mount point, sorted by mount point, **at most 8** (from at most 64 candidates), with the user-name rule of decision 9 for the mount point. A network share is **never asked for its size** (statfs on a share that cannot be reached can block) and is shown by its kind, never by its source; memory and overlay mounts get statfs sizes, `null` when it fails. The page lists the real file systems and these, so at most 16 entries.

**ST1.3 Marks and the warning on the page (fact).** The file system on the disk of `/` is marked as the boot and root medium with the sentence not to remove it while the device runs; it is never offered as removable, whatever its flag. A removable or USB disk is marked as a removable medium, to be removed only when the device is off. A memory mount is marked as not persistent; an overlay says that it depends on its layers whether changes persist; a share says that its data is on another device. The low-capacity warning is the existing alert of decision 8 with its thresholds (above 85 % relevant, above 95 % critical, real file systems only) and its texts. The boot medium comes from the detection (`GET /api/v1/device`, `boot_medium`).

**N1 and ST1 allow-list and unit (fact).** Added to the metrics allow-list that `TestMetricsOpenOnlyAllowListedFiles` enforces: `proc/net/wireless`, `run/systemd/resolve/resolv.conf`, `sys/dev/block/<major>:<minor>` (read as a link) and `sys/block/<name>/removable`; the test refuses `uevent`, `serial`, `cid` and `csd` and similar names. The service unit is **not changed**, as in N0.5: `ProtectSystem=strict` leaves `/run` and `/sys` readable, `ProtectKernelTunables=yes` makes `/sys` read-only and leaves `/proc/net` alone, and the unit sets no `ProtectProc`, `ProcSubset`, `InaccessiblePaths`, `TemporaryFileSystem` or `PrivateNetwork`. *Open until the device check:* that the service user reads the new files under the real hardening.

**N1 and ST1 API (fact).** Added fields only, schema version 1: per interface `ipv4_cidr`, `ipv6_cidr`, `signal`; `routing.dns.via_local_resolver`; per storage entry `device`, `disk`, `removable`, `usb`; the snapshot member `mounts`. No route was added ([`DASHBOARD.md`](../DASHBOARD.md#api)).

## Amendment: SF1 as implemented

Recorded with the pull request of the fix step SF1 (2026-11-28; `docs/ROADMAP.md`). It fixes the defect of ST1 and the minor finding of N1 from the device result above, within D-C104; no new decision. Class C (tests and CI against synthetic fixtures) until its device check; nothing is Verified.

**SF1.1 Root-field rule (fact).** An other mount (memory, overlay, network) is listed only when its root in `mountinfo` (field 4) is `/`; a bind mount is never listed, and of several entries of one mount point with root `/` the first counts, as before. The sandbox of the unit adds bind mounts of the tmpfs at `/run` (`/systemd/inaccessible/dir` over `/home`, `/root`, `/usr/lib/modules`, `/run/user`, `/run/credentials`; `/systemd/inaccessible/reg` over files under `/proc`) and the private `/tmp` (`/systemd-private-<id>/tmp`); none of them is listed now. A real file system is never taken from a bind mount either (the unit binds `/var/lib/oarfish`, `/var/cache/oarfish` and the private `/var/tmp` from the root file system); a btrfs subvolume, whose root is the path of its `subvol=` super option, is not a bind mount and stays listed. `ParseMountinfo` already kept the root; it now also keeps that option for btrfs, decoded and bounded like the mount point (fuzz target extended). Tests: `TestStorageServiceSandbox` with the synthetic fixture `pi-sandbox` (only `/tmp` remains), `TestStorageBindMountIsNeverAFileSystem`, `TestParseMountinfoRootAndSubvolume`.

**SF1.2 Size of `/tmp` (fact from the kernel's rules; device evidence pending).** Inside the service, `statfs("/tmp")` reaches the private bind. Its root `/systemd-private-<id>/tmp` is a directory of the tmpfs that the host mounts at `/tmp` (the same major:minor in field 3), and `statfs` reports the file system, not the directory, so size and use are those of the host's `/tmp`, private directories of all services included, as `df /tmp` on the host shows. There is no second way to measure it. The device check of SF1 compares field 3 of both tables and the sizes.

**SF1.3 Hidden addresses (fact).** Per interface the added field `ipv6_hidden` (schema version 1) counts the global IPv6 addresses that are left out because they contain the hardware address (EUI-64; not tentative, not failed). Only the number leaves the collector; link-local addresses and IPv4 are never counted. The page Netzwerk says under the addresses "Eine IPv6-Adresse ist verborgen. Sie enthält eine Hardwareadresse." or "2 IPv6-Adressen sind verborgen. Sie enthalten eine Hardwareadresse." (`docs/UI.md`). Tests: `TestNetworkHiddenAddressCount`, `Network.test.ts`; scenario `network-hidden-addresses`.

**SF1.4 Unchanged.** The unit, the allow-list (no new file is read), the update helper and the broker; only the main binary changes.

**SF1 open (finding, not fixed).** A real file system mounted where the sandbox puts an inaccessible directory (a separate `/home` partition, for example) is still listed, and `statfs` then reaches the overmount on `/run`, so its size would be wrong. The reference image has no such mount; not observed.
